# v0.5.0：供水、蒸汽和地面 T3

v0.5.1 保留以下工业能力，并修复新防空炮预算等待阻塞早期扩矿的问题。当前尚未实现全图持续占矿与旧传送带自动升级为钛带。

适用 Mindustry v146、赛普罗自定义进攻图，全部科技保持解锁。自主军工路线为 dagger → mace → fortress；T4～T5 与其他星球不在本轮适配范围。

## 发展顺序

先建立铜铅煤沙、石墨、硅、真实供弹和首批部队，再发展钢化玻璃、水与电力。附近有合适水面时使用机械泵；否则搜索可合法建造的抽水机，按实际地板与环境计算产水量。泵、导管、电站、电力节点均正常付费并逐步施工。

蒸汽电站需要真实煤和水。原版每台用水 6 单位/秒；机械泵、水提取率、发电功率和耗煤周期均读取游戏内容，不用建造价格代替运行成本。水源选址避开会争用水的相邻钻头、工厂和其他液体线路，后续选址也保护已分配的水源。当前液体适配仅处理单一水路，并非任意混合液体网络。

每组蒸汽工程包含专用激光煤矿，避开其他工厂争用燃料。矿机、完整水路、电站和连接节点一起核算预算，先保留建设材料；旧煤电负责启动抽水与激光采煤。电站以 30 秒观测窗口的实际发电效率验收，达到 90% 才计为已验收。可靠容量使用观测效率折算，断水、断线时不继续按铭牌功率计入。只有接入同一工业电网的蒸汽容量才能让自建煤电待机；供水失效时重新启用备份，并付费修复管线。原有未知高级电站不被自动拆掉。

基础矿业开始后，提前为一组完整蒸汽模块保留空间，包含矿机、水源、导管和电站，防止小矿机占满煤田或新兵厂的出兵通道封住未来电站。预留不扣材料，也不提前建造；专用煤矿按实际矿格产量至少覆盖电站煤耗的 125%，可以使用部分矿格，无需固定占满九格煤。

完成 T2、发现可采钍矿且已有蒸汽供电与足够电力预算后，保留 T3 建设预算，建立激光钍矿与回库线，再正常建设 5×5 多倍重构厂。v146 这一步建厂需要 650 钍；每次升级 mace → fortress 消耗硅、钛、钢化玻璃和电力。T3 本身不消耗液体，水用于支撑供电。完整配方依赖包含前置 dagger 与 mace 的成本。

## 自动物流与持续生产

钢化玻璃由铅和沙加工。窑炉、铅和沙的供应线、完整成品回库线路一起预检；旧矿的出口全部被占用时，可以正常付费建立专用铅矿与窑炉模块，再连接电网。专用加工矿不会被当成待接核心的普通矿。已有原料矿的剩余吞吐可以按各消费者的需求比例分配，满足余量后正常铺分支；专用弹药矿、蒸汽燃料矿和未知高级设施保持原来的分配。

T3 使用核心作为建材仓储：真实矿机、工厂先自动回库，三个过滤卸载器分别取出硅、钛、钢化玻璃，经桥与专用接入口送入多倍重构厂。它们正常减少核心库存，保留建设储备；仓储不能替代上游生产。三种材料的卸载器、完整桥接线路与重构厂采用整体模板，一起预留、核算和付费施工，避免建完重构厂后无处接料。完整产能需求包含 dagger、mace、fortress 三阶段，参考目标为每分钟一组 T3，仍受实际电力、运输、缺矿与原版单位上限约束。

地面传送带无法连通时，尝试普通传送带桥跨线。桥按原版范围、队伍与连接规则配置，端点检查收发方向和串料风险，不拆地图墙体来制造通路。新矿若已有具体消费者，会先检查矿机与完整运输线是否能一起施工，避免不断堆出无法供料的钻头。

核心入口拥挤时，可以复用经追踪确认只通往核心的传送带和桥干线。合流只接到能实际接收普通物品的端口；桥接收端必须由配置好的桥发送，不能把朝向接收端的普通带误认为已通。方向隔离的桥端口同样用真实运输与无串料测试确认。

核心满库不会关闭仍向重构厂直接供料的硅厂、窑炉；仓储线路则按核心库存回补。煤、沙仍不进入核心目标，也不安排机体日常手采。材料不足时优先完善上游与等待自动收入，原版生产与施工持续扣料。

矿业背压会统计运输和加工缓存，但施工储备只认核心中可支出的库存；独立容器或工厂里有材料，也不会因此让核心缺建材的矿线停产。窑炉的三条未来物资线路在施工前还会保留侧向隔离，防止尚未建成的成品线在投产后把钢化玻璃送回铅输入线。

早期矿区若长期无法再扩张，且已有实际硅产出、建设储备和足够电力，则在达到至少 50% 的目标原料吞吐，或硅、石墨实际库存已达到当前目标时，允许按库存间歇造兵，避免把额定扩产目标当成永远不能解除的禁产条件。正在施工或库存不足仍会暂停兵厂。

## 施工、单位上限与旧档

新局会在可用时预留 T3 扩展和出兵空间；不足时保留 T2，不覆盖未知高级工厂。建设预算只登记目标，不从库存预扣。冗余设施仍需替代产能实际投产后才允许正常拆除。

友军暂时站在预留施工位置时，保留 T3 预算与钍矿目标，通过正常部队命令清空场地。实际开工仍执行原版单位碰撞检查。工业电网使用完整电力节点寻路，检查原版范围、节点连接数与绝缘阻挡，正常付费连接远处矿机和工厂。

准备 T3 时，会为地面 T2 留一个正常单位名额，使新 mace 载荷能继续进入 T3。不会修改原版上限或删除军队腾位。旧档若已把 mace 名额占满，可能需要正常战损后才能继续重构；本轮没有运输机回收已部署单位的完整能力。首次验证建议使用新的“公平 AI - 工业发展”地图。

重构计数以原版生产事件为准，兼容同一 tick 直接交接到下一重构厂的情况。水站规划、物资职责与 T3 状态随存档保存；读档后重新观察实际供电，再恢复验收。

## Windows Java 17 启动入口

试玩包附带 `launch-java17.cmd` 和 `launch-java17.ps1`。将两者放在游戏目录（与原启动器、`jre` 文件夹同级），双击 CMD 即可调用已安装的 Java 17 启动原来的 `jre/desktop.jar`；不下载或替换运行环境，不修改原启动器。用 PowerShell 的 `-CheckOnly` 参数检查路径而不启动游戏；换机器时可传 `-JavaHome` 和 `-GameJar`，或设置 `FAIR_AI_RUNTIME_HOME` 为本机 Java 17 安装目录。

开发长测曾两次触发游戏自带 Java 16.0.1 的 C2 编译线程本机崩溃，日志中的编译对象分别为模组方法和游戏原有方法，尚不能据此确定根因。Java 17 对照与原运行环境的引擎检查分开记录，不把切换运行环境说成修复了 JVM 本身。

## 验证与限制

定向引擎测试覆盖真实泵水与耗水守恒、煤电启动抽水机、蒸汽净供电、备用煤电切换、断管付费修复、桥跨障碍、满核心入口汇流、三阶段载荷交接、五种耗材精确对账、满库继续向 T3 供料与真实存档读写。

自主开局另用固定种子的真实引擎长测验证，报告与源码、分发 JAR 绑定。测试夹具的电力源只用于隔离军工耗材计量；普通开局长测不放电力源或物品源，也不在运行中发材料。

拥挤基地、特殊禁用规则、无法连通的矿区和缺少合法水源仍可能使发展停在较低阶段。这不是所有社区地图的兼容性或胜率保证。原版内容参考：[v146 Blocks](https://github.com/Anuken/Mindustry/blob/v146/core/src/mindustry/content/Blocks.java)、[泵](https://github.com/Anuken/Mindustry/blob/v146/core/src/mindustry/world/blocks/production/Pump.java)、[传送带桥](https://github.com/Anuken/Mindustry/blob/v146/core/src/mindustry/world/blocks/distribution/ItemBridge.java)。

完整 T3 模板目前以碎片核心开局为主要验证对象，其他尺寸核心只在完整布局通过检查时采用。任意已有大型基地中的通用重选址尚未完成。
