# 赛普罗后期 AI 开发路线

适用版本：Mindustry v146，当前模组基线 0.3.1。本文是设计方案，未修改运行中的 AI 或模组安装。

## 1. 目标和既定规则

让 AI 从当前基础矿业、石墨、硅和 T1，逐步形成可持续的 T2、T3、T4、T5 生产能力。发展阶段用于组织决策，不限制已解锁科技；地图条件和现有资产允许时可跳过已有环节。

继续执行：经济优先、普通玩家的付费施工与生产规则、正常单位上限；煤和沙直供加工，不进入核心库存目标；机体不承担日常采矿；暂未完整支持的地图自带高级设施保留原状。高级设施的自动接管必须以其完整适配器通过验证为前提。

首条验收用主战线建议为 dagger → mace → fortress → scepter → reign，便于逐级验证。实战选线另由已探索地形、可通行路径、可见敌人和可负担产能决定；地面无法到达时可选择 flare → horizon → zenith → antumbra → eclipse。海军单独作为水域能力，不要求每张地图都发展。

## 2. 游戏依赖路线

| 阶段 | 建设重点 | 决策依据和通过条件 |
| --- | --- | --- |
| 基础自动化 | 铜铅煤沙、石墨、硅、供弹；造兵输入与成品运输 | 在无日常手挖和无持续人工搬料的条件下生产；维护通路与预算 |
| 扩展物流与公用设施 | 钛、钢化玻璃、跨线运输、水源、液体管网、蒸汽发电、电池 | 真实流量和同一电网供电验证通过，矿区和加工区能稳定交付 |
| T2 | T1 工厂、初级重构厂、石墨和硅扩产、载荷通道 | 连续产出并释放 T2；钛、水不是 T2 的硬配方要求，但可支撑自动物流和经济 |
| T3 | 激光采钍、钛/钢化玻璃扩产、T2→T3 重构厂 | 能付清建厂成本并连续补充 T3；建厂依赖钍，不能只检查每次生产的耗材 |
| T4 | 石油路线、塑钢、相织布、水和冷冻液、T3→T4 重构厂 | 液体连续供应、足够同网电力和大尺寸载荷通路均成立 |
| T5 | 巨浪合金、高吞吐硅/塑钢/相织布、冷冻液扩容、T4→T5 重构厂 | 完整上游能够重复补充 T5；仓储与分批工程预算可支撑建造 |

发电分支按成本和地图选择：燃烧启动，蒸汽作为早期稳定扩展；温差、钍反应堆、冲击反应堆是后续可选方案，不应强制每局全部建设。核电必须有单独的冷却、热量和停机控制；冲击发电必须另算启动电力，不能用尚未启动的发电量支持它自身的前置工程。

石油来源分别适配地表油源、孢子压榨和石油钻井，比较实际环境、建造依赖、土地、水和电力成本。缺乏可行条件时保留可持续的低一级军队并继续侦察，不无限尝试同一个高级目标。

## 3. 当前代码应如何拆分

`TeamBrain.plan()` 目前是顺序判断和遇到第一个任务即返回。后期不能继续靠添加几十条“没有某厂就建某厂”扩展；需要让它把同一工程交给调度器执行。

| 模块 | 职责 | 与现有代码的关系 |
| --- | --- | --- |
| `RecipeCatalog` + 设施适配器 | 配方、建筑费用、耗电、液体、矿物硬度、升级关系、特殊机制 | 替代 `producer()` 只识别简单加工配方的局限 |
| `EconomySnapshot` | 实际库存、窗口内生产/交付、消费者缺料、网络占用、发电和存储 | 从 `WorldView`、`EconomyMonitor` 和 `EconomyPlanner` 提取读取模型 |
| `DemandPlanner` | 从目标产量反推所有上游需求，决定扩产或升级 | 替代固定石墨/硅目标及全局产量相加 |
| `ProjectPlanner` + `ProjectScheduler` | 工程拆解、材料与供给预留、任务依赖、施工和故障恢复 | 保留 `project` 和正常建造执行器作为底层 |
| `LogisticsPlanner` | 物品、液体、载荷、电力连接和实际可达容量 | 逐步扩展 `Construction`、`RawLogistics`、`DefenseLogistics` |
| `MilitaryPlanner` | 目标兵种、单位速率、重构路线、升级/出兵分流、经济优先预算 | 扩展现有 T1 工厂选择，保留现有指挥器 |
| `IndustryController` | 依据适配器控制支持的工厂、重构厂和特殊发电设施 | 收紧当前 `manages()` 判断，保护未支持高级设施 |

开始用显式、可审计的适配器支持有限设施，不做任意模组内容的全自动配方推断。配方参数尽量读取实际游戏对象和本局倍率，避免把 v146 的数值重复硬编码在多个规划器中。

每个适配器至少提供：建造依赖、周期物品输入/输出、连续液体输入/输出、电力、可选增益、环境要求、候选布局、投产条件、运行控制和故障诊断。`GenericCrafter`、`AttributeCrafter`、钻头、泵、反应堆、兵厂和重构厂不能共用一个不区分语义的公式。

## 4. 用产量目标递归规划

内部统一使用游戏 tick 作为时间单位；展示时再换算物料/分钟、液体/秒和功率。必须区分：

- 建筑的一次性材料成本；
- 每次生产的批量材料；
- 持续消耗的液体和电力；
- 可选的水冷/地形加成；
- 产线停机后仍需处理的设施状态，例如反应堆余热。

例如目标每分钟生产 1 个 mace，T2 重构步骤本身需要每分钟 40 硅、40 石墨，以及运行电力；还要递归加上前置 dagger 的生产成本、建设储备和防御用料。不能把“库存有 40 硅”当成“具备每分钟 40 硅的可持续供给”。

基本计算：

```text
目标物料流量 = 军事连续需求 + 防御需求 + 其他工业需求 + 计划窗口内的库存补充
所需设备数量 = ceil(目标流量 / 单机可信有效产量)
消费者可用流量 = min(源端可分配产出, 实际运输可达容量)
项目可用库存 = 实际共享库存 - 已预留建设费用 - 防御储备 - 启动储备
```

可信有效产量依据实际矿覆盖、配方、液体、电力、地形、堵塞和观察窗口计算。先保守估计，再用实际生产/交付校准。核心库存净变化包含建造和造兵支出，不能直接当作生产量；满库造成的自然背压也不能误判为生产能力不足。

供给必须分配到具体生产者、消费者和网络。一个煤矿已经承诺给蒸汽发电的产能，不能再次完整分配给硅、石墨和弹药；孤立发电机不能计入另一电网的可用供电。缓存只能缓冲短缺，不能替代持续流量。

高级液体是重点：`GenericCrafter` 的液体输出可能是按 tick 连续输出，物品消耗则按制作周期结算。不能把冷冻液输出的 amount 再统一除以 craftTime。核电冷却有特殊热量逻辑，也不能仅按普通耗液消费者处理。

## 5. 工程必须以投产为完成标准

建议工程对象包含：目标能力、目标速率、配方选择、前置任务、完整空间预留、建设费用、运行输入、供给分配、验收窗口和故障原因。

```text
PROPOSED → FEASIBILITY_CHECK → RESERVED → BUILDING
         → CONNECTING → COMMISSIONING → RUNNING
                   ↘ BLOCKED / REPAIRING / CANCELLED
```

新建计划先检查整条链的可行性；从上游供给、公用设施、运输开始施工，再投放主要消费者。正常 `BuildPlan` 逐步建造，不能创建成品建筑或资源。阶段之间允许先建少量缓冲仓、逐段接线，工程状态必须清楚记录尚未兑现的依赖。

基础防御、断线修复、紧急电力和维持现有收入优先于扩张；扩张优先于非紧急造兵。这是当前经济优先策略的延续。军费消耗受预算与实际产线负载限制，不应因为正在补几段传送带就反复暂停所有军工。预留只作账面记录，不修改游戏库存。

施工资源不得重复承诺。大工程超过仓储容量时分批付费施工；单个建筑实际需求超过当前可用仓储时，先规划扩容。启动依赖成环时选择可负担的替代路线，例如先用气动钻头采钛，再用激光钻头采钍，不能指望需要钍建造的爆破钻头取得第一批钍。

工程规划状态、预算、设施职责和供给分配要能存档恢复。读档后先核对真实建筑、库存和连接，不能盲信旧标记或重复建造。相同失败原因进入冷却期；地图或网络状态发生变化后才重试。

## 6. 矿业、物流与重构的实现重点

### 矿业升级

机械与气动钻头都是 2×2；激光钻头是 3×3，爆破钻头是 4×4。后两者需要重新搜索矿覆盖、供电、可选供水和出口，不能套用目前同尺寸原位升级。

比较每个方案的新增稳定产量、整个工程成本、额外水电、可用矿覆盖、输送瓶颈和预计停工时间。旧矿不足时优先寻找新矿位；新方案投产后再付费拆除旧矿。不能为了“升级成功”先拆掉唯一收入线。水冷增益只有水能稳定交付时才计入。

### 自动物流

把核心入库、工厂直供和军工供给视作不同目的地，并为军事和建设分配容量。煤、沙继续直供工厂；塑钢、硅等既可回库，也可按预算直供下游，不能要求所有物料都先入核心。

物品物流需要支持交叉器、桥接、受控分流和卸载器；核心卸载必须配置物料并计入材料依赖，不能通过虚构库存或机体持续搬运替代。液体需要泵、管道、桥、容器、液体隔离及端口预留。网络必须验证输送方向、有效容量、共享争用、实际到货和毁坏后的恢复，而不只是图上连通。

布局从完整工程占地开始，预留后续大厂、物品入口、液体入口、载荷转向与出口。蓝图是候选布局模板，需要带有输入/输出、容量和环境等契约，接入失败就选其他布局，不能因为模板能放下便认定可投产。

### 重构造兵

通过 `UnitFactory.plans` 和 `Reconstructor.upgrades` 建立可升级单位关系。兵厂、重构厂之间用原版载荷机制连接；对每个目标兵种验证具体载荷通道的尺寸和容量，不假设一条载荷带能通所有等级。

T1/T2 等中间单位可能继续升级，也可能需要出厂投入战斗，必须设计分流和释放位置。优先新建对接生产线，不依赖把已经出厂参战的单位再次装回载荷。保留原版升级过程、资源消耗、时间和单位上限，不用删除低级兵再生成高级兵的方式代替。

不能拿“兵厂建筑存在”作为成功条件；需要观察原版升级完成、载荷成功输出和单位实际释放。支持断电保留进度、上游停供、出口阻塞、单位上限、战损和读档恢复。

## 7. 编码与验收顺序

1. **规划底座与自动物流**：增加能力注册表、实际经济快照、按消费者分配供给和工程状态；先迁移现有石墨/硅/供弹，保住 0.3.1 的公平性及零日常手挖回归；补齐工厂与兵厂自动输入、交叉/桥接。
2. **首条完整 T2**：先固定 dagger→mace 作为集成用例，算清前置 T1 与重构总成本，自动扩产石墨/硅，完成载荷对接及释放。通过后再接入空军与实战选线。
3. **液体和可扩展经济**：钛、钢化玻璃、水、蒸汽、电网与缓冲；此项与 T2 在代码上可分阶段推进，但不在产线未稳定时强行升级。
4. **T3**：激光采钍、异尺寸矿业迁移、T3 厂建造预算、连续 T3 补充和战损恢复。
5. **T4**：石油、塑钢、相织布、冷冻液，大厂完整布局及高负载验证；冷却适配稳定后再引入核电分支。
6. **T5**：巨浪合金、更大水电/冷却/物流与仓储预算，重复生产而非一次性吃完开局库存；最后扩展兵种组合与更复杂的战场选择。

每一阶段都要跑真实引擎集成测试与多地图持续模拟，至少包含平原、隘口、湖岸、缺少关键资源、拥挤开局、已有高级设施、持续战损和存读档。缺矿图允许停留在较低等级，但必须报告具体原因并继续可行的发展；关键资源不足不能让基础生产和防御一起停摆。

当前三个小型测试图的主要资源为铜、铅、煤、沙和钛，不能据此验收自建完整 T3～T5。保留它们作为基础回归，另增加有钍、可用水和可行石油路线的完整资源图，以及缺钍、无地表水、矿区狭窄、跨水域和拥挤高级开局等测试图；分别验证能够发展和应当选择替代路线的情况。

高级阶段的验收要求：不在运行中补资源；付清普通建造和生产成本；观察窗口内重复交付目标产物/单位；没有依靠日常手挖和持续机体搬运维持生产；供弹、基础收入和维修储备仍能维持。记录首次投产时间、后续有效产量、缺料/缺电/堵塞时间、建设投入、故障恢复时间和最后可持续等级。

观察面板应增加当前发展目标、所缺依赖、计划/实际产能、项目预算、工程状态、军工分流与停滞原因，例如：“T3 建厂缺钍 → 激光采矿缺钛 → 钛运输未连通”。这比只显示“缺少某资源”更有用。

## 8. 第一轮交付建议

把下一轮范围限定为：保留现有基础能力，建立通用工程/供给账本，完善物品自动物流，并完成一条能持续生产 mace 的自动 T2 线。无需第一轮就加入所有高级建筑或学习模块。T2 链将同时验证依赖展开、预算、扩产、运输、载荷和正常造兵规则，是后期系统的第一项完整验收。
