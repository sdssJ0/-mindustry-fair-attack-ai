## 2. 已确认且必须保持的边界

1. 首先支持赛普罗自定义进攻图，后续再扩展埃里克尔；全部科技解锁不等于必须按固定科技顺序发展。
2. AI 和玩家遵守相同规则：真实建造时间、材料、施工范围、生产耗材、弹药、电力及单位上限。不得直接生成成品建筑、单位或资源，不绕过地图禁用与迷雾规则。
3. 经济优先：先建立和维护上游自动化，再根据能力升级和造兵；允许必要的防守和短期应急。
4. 非必要不由核心机体日常手挖。正常开局依靠多矿点和自动运输；完全没有可支配启动材料时的有限自救不能变成日常生产方式。
5. 煤、沙作为原料直供工厂或其他有效消费者，不设运回核心的采矿目标。地图原有库存不删除；应急取用也不能替代建设上游。
6. 飞机或核心机体只允许承担前期短期补给、施工过渡或应急运输。有条件后必须建设可持续的固定物流，不因临时运输送得动而放弃建设线路。
7. 地图预置但尚未完整适配的高级设施保留原状，不擅自更改开关、控制程序、配方或拆除。接管之前先完成对应适配和验证。
8. 资源面板读取真实状态，预算只是账面分配，不能修改库存。学习能力与 API 不能代替可靠的本地执行系统。

## 4. 用户最终确认的策略要求

### 4.1 战损、危险区域与下游供应替代

发现工程位置处于持续敌方攻击下时，暂停不安全的施工和重建。记录地点、时间、可观察到的威胁、损失和受影响的职责；不能等反复损失很多轮之后才处理。

危险约束必须覆盖重建、扩矿、维修、物流、公用设施和后期改造等所有入口，防止一个规划器停建，另一个规划器在原地重新创建同一工程。

建立“资源点—运输网络—消费者”的供给关系，并据此处理：

- 炮塔供弹、关键供电或重要工厂依赖受损源时，优先寻找其他安全资源点并接入；检查替代来源有没有已承诺给其他消费者。
- 替代线路施工期间，计算消费者缓存和可用库存能维持多久，必要时短期调用库存、限产或暂停非关键消费者。
- 暂时无法恢复时，明确标记下游减产、停产及原因，不继续计入完整可用产能。
- 单纯回核心的矿线，也要检查核心建造和未来工程需求；没有紧急下游影响时，再权衡是否暂时放弃。
- 共享矿点、共享电网、共享运输干线不能重复分配同一份容量。

**用户最终决定：一般不考虑运输距离的经济代价，传送带廉价。** 安全的远距离矿区可以正常开发并拉线接入，不因线路长、铜材消耗或运距评分而放弃矿区或迁移工厂。线路长度可以影响实际施工顺序和恢复时间估计，但不能成为压制安全扩张的主要门槛。

优先避开敌方火力覆盖的矿区与线路。只有缺乏安全通路、原布局无法接入，或需要配合蓝图改造时，才考虑迁移、重构产线。

同时评估反击选项：部队攻击、可持续供弹或供电的前线炮塔、攻击暴露的补给与电力，或者转移开采。不能每受到一次攻击就强制报复。

危险区不是永久禁建，也不能只靠固定超时解除。敌方威胁消失、我方能够压制、路线变化或获得新情报后重新判断。未知攻击来源只能根据观测估计和侦察，不能读取迷雾内目标的隐藏位置。

### 4.2 战力评估、集结与撤退

军事任务拆分为侦察、骚扰、防守和强攻，条件分别判断：

- 侦察用于获得情报，避免无意义交战。
- 少量兵力可骚扰暴露经济设施，但需要有收益和退出路线。
- 核心和关键设施受到攻击时允许及时防守，不必等到强攻集结条件。
- 正面强攻按目标附近的防御能力集结，而不是固定四个单位或进入武装阶段后有兵就冲。

第一版可用简化战斗模型，以有效血量与有效 DPS 为基础，至少考虑射程、接敌耗时、空地攻击兼容、当前血量、护甲或护盾、弹药与供电的可观察状态、附近支援和路径。随单位阵亡更新输出，不能假定整个交战期间所有单位都保持完整 DPS。

可采用短步长近似模拟估计击毁时间与己方损失；估计值不能未经校准就显示为准确胜率。保留撤退和重新集结条件，避免攻击与撤退频繁切换。

当前兵种即使达到正常单位上限也无法有效突破时，改为升级兵种、换方向、打补给或前线火力推进。不能故意删除单位腾名额，也不能继续同路线持续送死。

前线炮塔作为进攻手段必须正常付费施工，并规划真实弹药或电力。评估建造机体和未完工建筑的暴露风险，遵守敌核心禁建范围等原版限制；尚未完工的火力不能计作当前已有战力。

### 4.3 库存、实际产能、需求与扩张

同时维护以下指标：

1. 可立即使用的真实库存，区分核心、生产设施、运输缓存和已承诺用途。
2. 实际生产与到达具体消费者的持续交付速率。
3. 在供电、供料、地形和正常出口条件下可信的可持续能力。
4. 当前运行需求，以及已经选择的建设、升级、军工和前线供弹目标。

低库存但净供给充足时，可等待积累并处理其他工作，不因总量少立即复制工厂或钻头。高库存但持续入不敷出时，应提前补产能。设备运行效率百分比与绝对吞吐量分别统计，不能把“小厂满效率”当作总产能充足。

目标资源流量来自工厂、燃料、弹药、造兵、建设补充和合理余量；沿配方反推上游，按消费者和网络分配容量。发展目标形成新增用途时，即使核心库存较多，也可以继续开矿或扩产。

缺电、缺另一种原料、出口受阻时，当前较低消耗不能被当作真实目标需求下降。满库自然背压也不能被误判为设备故障或产能不足。先区分原因，再决定加矿、加工、疏通或暂缓。

“AI 任何时候不应闲着”的落实方式是：有持续评估、有明确目标、有可行任务就执行。必要的材料积累、集结与侦察属于正常行为；无可行任务时显示等待原因和解除条件，不能为了保持动作而制造冗余建筑。

### 4.4 前期单厂、后期完整蓝图与改造

前期默认用单台加工设施，按真实配方与游戏机制建设原料输入、供电和出口；不强迫开局负担大型蓝图。

后期在原料、供电、空间和材料条件满足时使用完整工厂或发电蓝图，把原有线路整理为适配蓝图的产线。蓝图不是仅仅多放几台相同机器；必须识别内部拓扑、物料比例和外围供给。

改造按完整工程执行：选择蓝图与场地、准备供给和物流、施工接入、实际投产验收、退役被替代部分。有空间时先建立替代产能；空间不足时先准备过渡库存并分段施工，不先拆掉唯一关键收入或供弹链。

复用硅产线的规划框架是正确方向，但不能只替换原料名称。共用需求反推、预算、选址、连接、验收和故障恢复，另外为以下机制提供适配：

| 设施类别 | 必须区分的机制 |
| --- | --- |
| 固体加工 | 批量输入输出、制作时间、多原料比例、混料与出口背压 |
| 固体及液体加工 | 持续液体流量、独立管网、端口、实际到货 |
| 钻头、泵、地形设施 | 硬度、覆盖矿格、占地、环境效率、电力与可选水冷 |
| 高级发电 | 运行燃料、冷却、净供电、启动电力、预热和安全控制 |
| 兵厂及重构厂 | 真实配方、升级关系、载荷通道、释放位置和单位上限 |

工厂与发电蓝图应记录：来源和版本、占地、旋转方式、物品及液体端口坐标和方向、输入输出速率、电力连接、环境要求、启动条件及控制器职责。不确定的进料口或控制逻辑，适配时向用户询问，不盲猜。

用户本地蓝图目录为 `C:\Users\陆以恒\AppData\Roaming\Mindustry\schematics`；此前只做过清点，不代表已被 AI 学习或完整适配。目录是否仍存在、内容是否变化，导入前重新只读核对。现有额外蓝图入口为游戏数据目录的 `fair-ai-blueprints/`，也不能等同于适配完成。

部分蓝图可能含沙盒物品源、电力源、液体源或处理器。不能把带源蓝图当作合法生产；也不能简单删掉源或控制器后宣称其能够稳定运行。需要明确外围真实供应，理解或替代必要控制，再做有限资源验收。

高级钻头按真实矿格、硬度、供电与必要物流选址；异尺寸升级必须重新规划。后期扩展发电和炮塔时，分别理解燃料来源、冷却、弹药、供电与攻击对象，避免只有建筑没有运行条件。

### 4.5 自动运输、沙子背压与钛传送带

每项临时机体运输都应有明确的退出条件和待建设固定物流。永久路线建成、实际到货通过后停止对应日常搬运。自动化验收应包含无人持续搬料时的运行表现。

截图中的沙子堆积是待诊断的现象，不能仅凭截图认定唯一原因：

- 独立沙带满、下游已满产：允许降低开采或暂时关闭部分供给。
- 沙子占用共用通路并阻塞其他原料：分线、限流或调整接入口。
- 下游缺煤、缺电或出口堵塞：修复对应瓶颈，不能持续追加沙钻头。

不要以把煤沙倒进核心、持续飞机清运或无需求焚毁作为默认解堵办法。

**用户最终决定：钛传送带廉价，不增加复杂的升级收益门槛。** 先完成钛矿、回库线和基本稳定的钛、铜等建材供应；具备正常施工材料后，可以逐步广泛替换已有普通传送带。

- 不要求线路满载，不要求先证明普通带已限制钻头产量，不要求逐段计算投资回报。
- 可先换高流量矿区出口、生产干线和供弹线，再覆盖其他普通带；这只是施工顺序，不是升级资格限制。
- 正常材料不足时等待或调度其他工作，不添加任意的高库存阈值或长期复杂储备门槛。
- 按正常建造规则消耗材料与时间，保持朝向、配置及既有连接，覆盖替换或分段施工不能破坏供给职责。
- 分流、桥、混料和下游堵塞的诊断仍然保留，但不作为允许升级普通带的前置审批条件。
- 不把此项解释为强制替换所有其他运输设施；桥、交叉器、特殊传送带按其机制保留或独立适配。

v146 内容定义中普通带与钛带标称吞吐量约为 4.2 和 11 物品/秒；复杂网络以真实运行结果为准。

## 5. 建议实现拆分与优先顺序

以下是职责建议，不要求照抄类名，也不要求一次重写全部控制器。优先保住现有自动化与公平性回归。

| 优先级 | 工作包 | 可审查的完成结果 |
| --- | --- | --- |
| P0 | 统一威胁判断、战损记录、危险工程控制 | 已知持续火力区不再重复送建筑，所有规划入口遵守同一限制 |
| P0 | 供应关系与断供应急 | 暂停受威胁工程后能定位下游、改接安全远矿或明确减产 |
| P1 | 军事任务、简化交战估计、集结及撤退 | 早期可骚扰，后期不因有少量兵就冲强防线；能选择替代战法 |
| P1 | 需求与实际交付模型、工程调度 | 库存与流量共同决策，无关任务不被可选工程预算永久阻塞 |
| P1 | 固定物流补齐、堵塞诊断与广泛钛带升级 | 日常生产摆脱持续机体搬运，基础供应稳定后正常升级 |
| P2 | 单厂通用框架、完整蓝图契约与分段改造 | 基础线可逐步迁移至高效模块，不先破坏关键供应 |
| P2 | 高级矿业、能源、炮塔和 T4/T5 配方适配 | 每个设施都有真实完整上游、启动条件和持续生产证据 |
| P3 | 共享数据接口、程序 AI 与 API 对照 | 在可靠执行能力上比较战略收益与 token 成本 |

建议的模块边界：

- 观察与经济快照：从真实对象采集不可变状态，区分观察事实和估计。
- 威胁与战损：局部火力、工人路径、最后可见情报、地点损失及重评条件。
- 供给关系与需求规划：生产者、消费者、物资、电力、液体和已承诺容量。
- 工程调度：前置条件、预留、建设、接线、投产、受威胁暂停、改造和退役。
- 军事规划：目标、任务、可用兵力、交战估计、集结、撤退与前线工程。
- 设施与蓝图适配：配方和特殊机制，完整接口与运行验收。
- 观察及行动接口：程序 AI 与未来 API 共用，最终调用现有合法执行器。

保存需要恢复的工程职责、替代关系、必要预算和危险记忆；读档后重新验证真实对象和当前情报。不能把过期的敌位置或旧供给分配无条件当作当前事实。

## 6. 需要覆盖的验收场景

下表是新开发应补充的目标，不是本次已经通过的测试。

| 场景 | 预期表现 |
| --- | --- |
| 敌炮持续覆盖钻头或运输线 | 不反复在同一火力区重建；工人也不持续进入送死 |
| 被封锁矿源负责炮塔或发电 | 识别消费者；改接安全来源，或短期缓冲并显示减产风险 |
| 替代矿区很远但线路安全 | 正常规划远距离固定物流，不因运距而拒绝 |
| 原矿只补核心，其他供给足够 | 可以暂时放弃，仍持续评估建设材料需求 |
| 一个煤矿服务多个消费者 | 按真实可分配产能分配，不重复记账 |
| 敌炮被清除、威胁再次出现 | 条件变化后恢复或再次暂停，避免固定冷却导致盲目复建 |
| 后期少量单位面对强防线 | 集结、撤退或改变战法，不连续同路线送死 |
| 早期暴露目标与核心遭袭 | 可执行有限骚扰和必要回防，不被强攻门槛一起禁止 |
| 低库存、高持续净供给 | 能等待积累，并安排其他工作；不盲目扩同类产能 |
| 高库存、持续供不应求 | 提前扩产；核心满也不关闭仍直接供应前线的设施 |
| 缺电或另一原料导致减产 | 定位真正瓶颈，不误报为需求低或继续复制无效矿机 |
| 独立沙带满与混料堵塞 | 分别进行背压控制和通路修复，不依赖飞机长期搬走 |
| 钛铜供应稳定、普通带尚未满载 | 仍允许广泛升级，实际扣料耗时，方向和供给保持正确 |
| 原料与弹药临时机体配送 | 固定线路投产后退出对应日常运输，独立运行仍可持续 |
| 后期蓝图改造与空间不足 | 正常分段建设、验收及拆除，无唯一关键供应先被拆断 |
| 高级发电启动、断料、断水 | 不用未来电量启动自身；正确诊断并处理对应特殊机制 |
| 迷雾、读档与多个地图 | 不泄露隐藏信息，恢复任务并重核实际条件 |

新测试应使用真实 v146 引擎验证有意义的行为与资源守恒，再做多地图持续模拟。定向夹具可隔离变量，但必须明确区分夹具能力与 AI 自主能力。不能靠给料、免费建筑或强制完成工程宣称 AI 已通过。

至少观察：有效产量与交付、关键断供时间、施工与战损、实际出厂单位、进攻损失、替代供应恢复时间、正常拆改、手挖及日常搬运占用。库存净变化不等于生产量；生成计划不等于投产；单局达到某等级不等于稳定上限或胜率。

资源窗口后续应能解释：当前工程、等待原因和解除条件、库存及供需、被暂停区域和受影响消费者、替代路线、军队任务、集结或撤退原因。不要只显示“经济就绪”却没有下一步。

## 7. API 方案：后续可选，不属于当前实现

### 7.1 结构化状态与动作

可从模组内部读取游戏对象生成状态，无须靠截图操作，也不需要读取进程内存。数据分层包含地图地形及矿区、唯一建筑实体及占地、己方库存和运行状态、单位与编队、供给网络、危险区、工程目标和蓝图目录。

多格建筑只建一个实体，格子引用实体 ID。编号需要字典、版本与单位说明；数字越短不保证越省 token，也不能用晦涩编码替代语义。

API 接收摘要及必要局部细节，发出开发矿区、设置产能目标、暂停区域、选择模块、集结或攻击目标等高层动作。本地完成合法性检查、选址、寻路、铺带、施工和战斗微操。

流程：游戏线程采集快照 → 公平视野过滤 → 摘要与候选方案 → 异步 API → 游戏线程重新验证 → 原版执行 → 实际结果反馈。

敌方库存、迷雾内位置等不应通过内部数据泄露。使用最后可见信息时记录时间和不确定性。回复携带的世界版本、对象和工程条件可能已过期，必须检查后再执行；超时、断网和错误回复时退回程序策略，不阻塞游戏更新。

### 7.2 token 估算与预期收益

以下仅是前期预算模型：每次 5,000 输入 token、300 可见输出 token，运行一小时；不是实测，也没有选定 API 厂商或模型。

| 固定调用间隔 | 每小时调用 | 输入 token | 可见输出 token |
| --- | ---: | ---: | ---: |
| 60～120 秒 | 30～60 | 15万～30万 | 0.9万～1.8万 |
| 15～30 秒 | 120～240 | 60万～120万 | 3.6万～7.2万 |
| 每秒 | 3,600 | 1,800万 | 108万 |

事件触发、工具查询、重试和模型推理会额外消耗；有推理 token 的模型不能只统计返回指令长度。具体费用依厂商、输入输出价格、缓存及推理设置重新核算，不在交接文档固定价格。

建议程序持续运行，API 低频评估总体战略，丢失重要矿区或进攻连续失败等关键事件再触发。规则、蓝图接口等稳定内容与变化局势分开组织；避免整局历史无限累加。缓存必须按实际模型支持情况与使用记录评估。

配比、传送带升级、堵塞和短时战斗控制优先由程序完成，确定性收益更高。API 的潜在价值主要在多目标取舍、预算协调、陌生布局与战略调整，不能补上本地根本没有实现的工厂或物流。当前无法给出可信胜率提升百分比，频率提高也不保证效果提高。

后续同图、同规则、多种子对比纯程序与混合方案，记录发展速度、战损、胜率、延迟、错误动作和每局 token 成本。调用 API 不自动产生持久学习；若要学习，另建回放、评价、参数或策略更新流程。
