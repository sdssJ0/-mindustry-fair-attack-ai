# 公平 AI 进攻 · v0.3.1 原型

针对本机 Mindustry **v7 Build 146 / Windows 桌面版**。用于**赛普罗自定义进攻图**，全部科技保持解锁，不修改战役科技树。程序策略，无 API、无模型服务费用。

## 安装与试玩

GitHub 用户可直接下载 [0.3.1 模组 JAR](releases/v0.3.1/fair-attack-ai.jar?raw=true)，或下载含三张测试地图的 [0.3.1 试玩包](releases/v0.3.1/fair-attack-ai-0.3.1.zip?raw=true)。游戏中导入 JAR；ZIP 试玩包需要先解压。源码构建生成的 JAR 位于 `build/`。

1. 游戏主菜单 → **模组 → 导入模组**，选择 `build/fair-attack-ai.jar`，按游戏提示重启。
2. **设置 → 公平 AI 进攻**，勾选“自定义进攻图启用公平 AI”。
3. 自定义游戏中选择一张**进攻图**并开始。也可进入已有进攻对局后，在同一设置页选择“启用本局 / 查看 AI 状态”→“启用本局”。
4. 状态窗口可以查看各队 AI 正在采矿、建设、补给还是集结。默认右上角显示资源摘要；设置页的资源窗口可以查看核心库存、净变化、电网、单位和炮塔真实弹药，以及实际搬运记录。当前资源观察仅在单机或主机提供。

本版采用**经济优先**：先建设原料与加工产线，正常付费升级矿业，连接工业电网并积累建设储备，再轮换集中造兵。资源不足或正在施工时可以暂停兵厂，暂停保留原版生产进度。因此首次出兵通常比 v0.2.1 晚；可以在资源窗口查看暂停原因和计划供需。

本轮默认只接管已支持的基础加工及空/陆军工厂。地图自带的未支持高级工厂保留原有生产开关、配方和原料线路，避免基础预算规划误停高级设施。

### v0.3.1 自动矿业与供弹修复

- 取消日常手挖补库存。前期优先扩建多座铜、铅矿机及实际入库线路，目标基础吞吐为铜 90/分钟、铅 60/分钟；已有自动收入时，即使库存暂时耗尽也等待产线产出。地形和预算可能限制扩张。
- 核心机体只在缺少产线启动材料、没有对应自动收入且材料可手挖时应急采矿；不会为了达到库存目标常驻挖矿。资源窗口显示本次运行的应急采矿时间。
- 双管炮使用铜、分裂炮使用铅，优先利用现有矿机的相邻直供；保持原有入库传送带方向。没有可用直供位置时，一起预检炮塔、专用矿机和运输线的合法位置与预算，无法连通就暂缓新增炮塔。冰雹炮使用石墨，建立煤矿、石墨压缩机及输出线路。也可为接受铜、铅、石墨、钢化玻璃的其他物品炮塔规划基础供弹；复杂地形仍可能导致选址/接线失败。
- 已有炮塔缺少支持的自动供弹链时，暂停继续堆放更多炮塔，优先补上采矿、加工或运输。供弹源与建设资源回库线路分开分配，断线后重新规划正常付费施工。
- 弹药厂保持运行，通过原版库存背压自然停产；核心库存充足不会关停专用弹药厂。炮塔周围保留供料入口，避免普通矿线或其他工厂封死入口。
- 社区加工蓝图按实际原料供给位置重新布置；无法合法平移的模块退回普通付费单机建设，避免模板只靠近核心却接不上原料。
- 当前没有完整支持的高级弹药产线会在资源窗口明确提示。支持的供弹链也不保证在所有炮塔持续满射速时都有充足吞吐。

附带 `build/test-maps/` 的三张 `.msav` 地图：**平原、隘口、湖岸**。在**编辑器 → 导入地图**导入，再通过自定义游戏选择**进攻**模式。地图设置了公平 AI 标记，安装模组后会自动启用。双方有镜像矿区和相同初始库存。

GitHub 中的独立地图位于 [`test-maps/`](test-maps/)。[0.3.1 验证报告](docs/reports/v0.3.1/report.md)包含 173 项引擎检查及四场持续模拟的结果；[后期发展路线](docs/LATE_GAME_ROADMAP.md)说明 T2～T5 的计划，尚未实现的能力不属于当前版本功能。

普通地图需手动启用本模式。取消勾选只影响之后打开的普通对局；已经启用的存档会保留模式标记，读档时继续运行 AI。

## 已实现

- 一个敌队对应一个 AI 玩家和一架正常核心机体，使用玩家相同的死亡重生流程。
- 使用原版 `BuildPlan → BuilderComp → ConstructBlock` 建造，不直接生成成品建筑。正常检查材料、施工距离、施工时间、位置和单位阻挡。
- 使用正常采矿与背包搬运接口，不直接向核心添加资源。机体搬运受移动速度、背包容量和交互距离约束。
- 关闭无限建造资源、免电免料、无限单位弹药、原版基地 AI 和额外核心机体生成。
- 关闭免费波次，正常工厂消耗资源和电力生产部队，使用普通队伍的单位上限。
- 接管进攻图原有建筑、已有部队和库存，运行期间不补满核心；根据物流策略，通过正常施工拆改运输线路。
- 按矿区与地形搜索钻头位置。铜、铅等建造物资运入核心；煤、沙作为加工/燃料原料，钻头先在本地保留产出，再直送工厂或发电机。
- 建立基础石墨、硅、煤电与造兵经济；按配方、生产周期、钻头有效矿格与硬度计算每分钟供需，配对原料吞吐和发电燃料消耗，避免库存低就重复扩厂。
- 优先选择矿格覆盖较好的矿位，材料允许时建设气动钻头，并通过正常玩家施工规则升级机械钻头。合并工业电网后才计算可用发电容量，不把远处孤立的发电机算进本地供电。
- 开局优先建设铜、铅、煤、沙的钻头，已有库存不会代替上游产能。加工厂、发电机和造兵工厂在建设前先检查物品供给依赖，缺上游时优先建设上游。
- **煤和沙没有核心库存目标，也不安排回核心的采矿、收货或搬运。** 工厂尽量靠近原料钻头，并分散使用矿点；需要远距离运输时，正常建设直达消费者的传送带。旧版普通传送带通往核心的原料入口会通过正常拆除关闭，贴核心直接倾倒煤/沙的钻头会重新选址。已经在旧线运输的原料可能在拆除完成前抵达核心，不会通过改库存来抹掉。
- 原料搬运的目标满载、被毁或不存在时，重新选择消费者；没有可用消费者则保留货物，仍可继续正常施工，不回退到存入核心。“物品只能存入核心”规则也不会使煤/沙入库；此时依靠真实传送带供料。地图原有的核心煤/沙库存不会被删除，满足供给检查后可正常取出用于加工。
- 资源面板额外显示煤/沙在矿点、运输线和工厂中的物品缓存，与核心库存分开统计。
- 接手地图已有工厂时，同样先补缺失的上游。普通补给优先取生产建筑的产出；从核心补给前检查基础供给是否存在，并动态保留当前施工及后续发展预算。基础手工补给保留量为铜/铅各 40、石墨 20、硅 60，尚未建成陆军厂时会增加相应储备。预算不凭空扣除或修改库存；紧急炮塔补弹可以使用保留量。
- 石墨、硅等加工成品正常铺设回核心的传送带，降低核心机体手工收货负担；已有可靠原料线的工厂不再重复安排原料手搬。
- 新线路标记运输物资，避开其他物资的钻头、工厂及会侧送进来的传送带。矿位和加工厂选址也检查串料风险；线路物资标记通过存档保存。
- 零库存时允许核心机体手采启动材料，再按正常造价建矿线；不能手采或没有已知可用矿区时，不会免费补料。新的建设任务可以撤销尚未取货的普通搬运，已携带的货物先正常送达。
- 内置 17 张有授权的社区蓝图，按地形、矿物、预算、危险与产能需求选择，可旋转、缩减为单机/双机模块、降级传送带，并过滤测试资源源/汇及导入的逻辑程序。裁剪后的加工/造兵模块不保留失去完整供应关系的原物品线路，由规划器重接真实供料和回库路线。设置页可查看来源并重新载入；额外 `.msch` 可放入游戏数据目录的 `fair-ai-blueprints/`。
- 炮塔选址考虑敌军方向、核心距离及附近地形；敌机接近时优先防空；补充炮塔弹药。
- 集结小队后进攻，近距离敌军触发回防，低血量单位撤退。
- 战略观察与选敌使用独立的己方视野，不使用原版赋予敌方 AI 的全图迷雾查询特权。
- 正常保存和恢复 AI 核心机体，避免读档重复发放机体。

## 当前能力边界

这是持续开发中的程序 AI，**全部科技解锁不等于已经写好所有科技的自主使用策略**。

- 从零发展的策略主要覆盖铜、铅、煤、沙、石墨、硅、基础矿业和初级造兵。完整油、液体、多级重构厂与 T2～T5 自主发展仍需后续实现，原有高级建筑不会被禁用。
- 部分兵厂输入和弹药补给仍由核心机体手工搬运；运输与电网被多点破坏时，恢复能力仍然有限。
- 当前产能模型是无水冷、无超速增益的保守额定估算，加入了配方、发电燃料、原料分配和工业电网检查；尚未完整求解液体、复杂分流、运输延迟及全地图最优布局。理论供给存在也不等于实际满负荷运转。
- 直送路径目前覆盖相邻建筑与普通传送带；不会完整分析任意地图已有的路由器、桥、质量驱动器等复杂混合物流网络。旧版普通钻头到核心路线已经验证可迁移。
- 已知矿区缺失或无法合法建设时，相关普通补给可能暂停；核心现有库存仍可用于正常施工和紧急炮塔补给。迷雾地图需要实际侦察后才能选择矿区。
- 地形适配经过三张小型测试地图验证，尚未验证所有原版或社区进攻图。非常拥挤的基地、缺矿地图、特殊逻辑脚本和混合星球内容可能使 AI 停滞。
- 保留原有基地和库存，因此任意进攻图的**开局资产可能不对称**。测试地图采用镜像资源和相同库存。
- 暂不支持埃里克尔。桌面 v146 已验证；Android 打包、其他版本与多人实战尚未验证。联机时所有客户端都需要安装同一版本，因为核心机体包含自定义实体注册。
- 战略视野记忆在读档后重新侦察；尚未保存完整战略任务队列，未完成的施工会尝试重新接手。
- 在“物品只能存入核心”的特殊地图规则下，手工工厂补给受原版规则限制，不会绕过限制。

## 构建与验证

源码位于 `src/fairai/`。需要 Python 3 和 JDK 17+。本机已找到的 JDK 会被默认使用；换机器时设置 `FAIR_AI_JDK` 为 JDK 所在目录。编译依赖取自上一层游戏的 `jre/desktop.jar`，不会把游戏本体打进模组。

```powershell
python .\tools\build.py --test
python .\tools\package.py
```

脚本使用 Eclipse ECJ 编译器，并生成 Java 8 字节码，兼容本机游戏携带的 Java 16。首次缺少编译器时从 Maven Central 下载并检查 SHA-256。测试数据写在本模组的 `test-output/` 中，不读取或覆盖玩家存档。

集成测试使用**本机真实 v146 引擎类**和无图形界面环境，验证建造耗时与精确扣料、无料停工与补料恢复、真实弹药消耗、规则及单位上限、迷雾过滤、三种地形的实际运输、三图自主经济与造兵出击、核心机体死亡重生和实际存档读写。也验证高库存开局仍先建矿线、接手工厂先补上游、零库存启动、真实产出直送、启动材料保留、蓝图解码改造及实际施工、资源监控不修改库存。没有把“生成建设计划”当作“建筑已正常运转”。图形界面的完整对局体验和长期平衡仍需实际试玩。

v0.3.0 另验证正常钻头升级的耗时与扣料、工厂暂停不清空进度、建设预算不扣库存、孤立发电机不计入工业供电、线路无串料、以及空传送带的物资标记在真实存档读写后仍有效。经济优先回归测试允许先完成基础产业与升级，再验证 20 分钟内的造兵和出击。

v0.3.1 共 173 项真实引擎检查通过，新增正常开局零手挖、空库存等待自动收入、多铜铅矿线、断供修复、停止控制器后独立补弹、石墨弹药加工，以及三图炮塔实际有弹且位于己方核心附近的检查。另有四场各 20 分钟的固定种子模拟，验证入口为 `tools/audit_automation.py`，报告与证据包位于 `build/reports/v0.3.1-fix/`。`tools/install-current.ps1` 只安装与此验证证据匹配的 JAR，备份并原地更新所有同名模组档案，安装后需重启游戏。

## 后续经济规划建议

下一步适合加入实际运行吞吐反馈、液体与蒸汽供电、钛及 T2 重构发展路线，进一步减少远距离矿点和手工兵厂补给。

规划状态应区分“缺上游”“施工中”“缺料”“缺电”“运输堵塞”和“正常生产”，为任务保留材料并设置观察窗口；后续再用投产时间、有效产量、停工时间及成本评价蓝图。学习模块适合在这些可执行且可评估的方案之间作选择。

## 源码结构

长期经济评估工具：

```powershell
python .\tools\benchmark.py --scenarios flat,choke,lake,rich --seeds 17,43 --minutes 30
```

结果写入 `test-output/benchmark/`，包括逐场 JSON、日志、最终存档和矿点额定供给检查。`rich-start` 用于富库存对照，`attrition`、`choke-attrition`、`lake-attrition`、`rich-attrition` 用于持续战损产能诊断，`duel` 用于镜像 AI 对战；压力场景中的定期单位死亡仅存在于评估程序，不属于模组功能。`flat-no-blueprints` 和 `flat-no-blueprints-attrition` 提供关闭蓝图的对照。全部生产计数来自引擎更新，评估不会修改 AI 决策代码。

可用 `tools/summarize_benchmark.py <结果目录...>` 生成当前策略报告、CSV、曲线、布局图和证据包；绘图需要 matplotlib、numpy。它会检查源码摘要及模拟 AI 类与分发 JAR 是否一致，不能把旧版本数据当成当前源码的评估。v0.2.1 首轮 17 组原始报告保存在 `build/reports/v0.2.1-ceiling/`；跨版本对照使用 `tools/compare_benchmarks.py`，v0.3.0 对照报告位于 `build/reports/v0.3.0-comparison/`。

- `FairAiMod`：模式启用、生命周期、规则和设置入口。
- `BotPlayer`：正常玩家重生流程与服务器控制的核心机体，处理原版远程玩家插值问题。
- `WorldView`：己方视野、资源与威胁观察。
- `Construction`：合法选址、造价预算、钻头与运输线路规划、工厂出口预留。
- `TeamBrain`：资源目标、依赖处理、施工、搬运、供电与部队指挥。
- `RawLogistics`：煤/沙直供策略、加工区选址、消费者运输线路与旧核心入口迁移。
- `EconomyPlanner`：每分钟产能与需求、矿业升级、工业电网、建设储备及经济优先的生产控制。
- `DefenseLogistics`：基础弹药选择、自动供弹链、供料源分配和断线修复；新增基础炮塔需先确认可直供或整体施工连通。
- `BlueprintLibrary`：社区蓝图、过滤、改造与合法选址。
- `EconomyMonitor`：玩家可见的实际资源、电网、弹药和搬运记录。
- `test/fairai/SimulationTest`：真实引擎集成测试与测试地图生成。
